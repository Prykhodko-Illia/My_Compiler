   What the AI did (Task 1 - the front end):

   PDF line for line, and that all six parser errors in the PDF come out with the same message and

   passing. Committed as "Task 1: ...". Also saved two notes in its own memory for later sessions:
   commits in this repo carry no AI attribution, and the tests run in the VM.


3. Prompt:
   "committed, let's do task 2"

   What the AI did (Task 2 - scopes):
   Replaced the flat symbol table with a stack of frames: the program has the bottom frame,
   visit_block pushes and pops one, a declaration is checked for a duplicate in the top frame only
   (so shadowing with any type is allowed), and lookup walks the frames from the top down. Added the
   two bool rules (the if condition, the operand of '!'). The redeclaration message became the PDF's
   "already declared in this block" everywhere, which changed tests/err/redeclared. The code
   generator got a temporary "not supported yet" stop for if and '!' until Task 3. Added the PDF's

   the then block used in the else block), and checked with a short script that the three x of the
   warm-up program resolve to three different declarations. 60 tests passing. Committed as
   "Task 2: ...".


4. Prompt:
   "committed, let's do task 3"

   What the AI did (Task 3 - basic blocks):
   visit_if appends then / else / merge blocks and ends the current block with a cbranch on block
   objects; each arm gets a br to merge only if the block the builder ended up in is not terminated
   (an exit in an arm already has its ret; a nested if moved the builder to its own merge).
   alloca_in_entry() puts every alloca at the top of the entry block in declaration order and goes
   back; the store stays in place. '!' is builder.not_. Added eleven programs to tests/ok, each with
   .expected and .ast: the PDF's 15 and the warm-up's 20, if without else, shadowing with another
   type, an exit in one arm and in both, '!' in a condition and its precedence, the variable assigned
   in both arms, and an if inside an else. Checked every output with LLVM's verifier and through
   lli, two programs through llc + clang, and that opt -passes=mem2reg prints the PDF's
   "%r.0 = phi i32 [ 1, %then ], [ 2, %else ]". Updated README.md for if / else, '!', scopes, basic
   blocks and opt. 71 tests passing. Committed as "Task 3: ...".


5. Prompt:
   "committed, let's do the while task"

   What the AI did (additional task - while):
   while became a keyword, a parse_while method and a WhileNode; the semantic pass checks its
   condition with the same helper as if, and the body is an ordinary block with its own frame. The
   generator emits cond / body / end blocks, with a br from the body back to cond (the back edge)
   unless an exit in the body already ended it. Added five ok programs (the PDF's 55, a loop that
   never runs, an exit inside the body, nested loops, shadowing inside the body) and four error
   programs (a non-bool condition, '{' on the while line, a body variable used after the loop, an
   empty body). Showed the IR with the back edge, the two phis mem2reg makes in cond, and 55 as a
   native binary. Updated README.md. 80 tests passing. Committed as "Additional task: while".
