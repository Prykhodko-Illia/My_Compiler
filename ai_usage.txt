3. Prompt:
   "Yes, do extern"

   What the AI did (additional task - extern fn):
   - lexer: `extern` is a keyword (sub "linkage").
   - ast_nodes: ExternFnNode, a FnNode with no body, its own visit_extern_fn.
   - parser: parse_extern, among the fn declarations in any order with them; the rest of the
     signature line is shared with fn (parse_params_and_result). Errors: a '{' on the line
     after it ("extern function 'twice' has no body: it is defined in C"), extern in a block,
     a function body or a struct ("'extern' is not allowed here"), extern after the statements
     (the same message as for fn), extern without fn.
   - semantic: externs share the function table, so a name declared twice gives the fn
     message. check_extern: only i32 and i64 parameters and results, with the PDF's messages;
     the C name may not be one the module already uses - main, printf, scanf, the generator's
     global strings, fn_<name> of the program's own functions, Struct_method of a member
     function. Those IR names moved to a new src/ir_names.py, which codegen and the checker
     both use, so the check cannot drift from what codegen emits.
   - codegen: an extern is declared under its own C name, before the member functions and the
     strings take theirs; no body.
   - optimizer: an extern is counted like a global function (no calls -> removed) and is always
     "with an effect", so a call of one is never dropped.
   - tests: tests/ffi/geometry.txt with geometry.c and two sessions (-3 4 -> 7, result 5;
     2 3 -> 5, result 3); run_tests.sh builds tests/ffi like tests/io and links NAME.c;
     tests/ok/extern_libc (abs and llabs from the statements, a function and a member function,
     under lli); 19 tests/err (the nine the PDF lists plus main, scanf, an fn_ name, extern in a
     struct and in a function body, declared twice, the same name as a fn, a missing fn, the
     wrong number of arguments, an i64 into an i32 parameter); tests/opt/extern_unused (an
     unused extern removed, declarations calling one kept).
   - grammar.ebnf and the docstrings updated.
   Checked by hand: nm geometry.o shows U abs and U isqrt next to U printf and U scanf, the link
   fails without geometry.c ("undefined reference to `isqrt'"), and both geometry sessions
